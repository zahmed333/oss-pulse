# Launch kit

Everything needed to post oss-pulse on X, and the reasoning behind each piece. Nothing
here is posted automatically; the drafts are for a human to edit and send.

## The one thing that decides this

A tool spreads on X when a stranger can repeat the result in one line and screenshot it.
That means three things have to exist before any post goes out, in this order:

1. A 15-second clip of the verdict landing. Done: `docs/brand/demo.svg`, generated by
   `scripts/render_demo_svg.py` from a real run against `examples/take-home`.
2. A one-line install. `install.sh` installs into its own virtual environment.
   PyPI is still the better home for it, and only the maintainer can publish.
3. A hook about the reader, not the tool. "A recruiter sent you a coding test" reaches
   every job-hunter on the timeline. "Supply-chain lakehouse" reaches twelve people.

## Thread (draft)

Post 1: the hook, with `docs/brand/demo.svg` attached as an image or a 15 s screen
recording of it:

> A recruiter sends you a take-home. You open the folder in VS Code to read the code.
>
> That is the whole attack. `.vscode/tasks.json` with `"runOn": "folderOpen"` runs a
> script the moment you trust the folder. It is called Contagious Interview. It has been
> running since 2023, and it targets developers on job boards.
>
> I built a scanner that reads the folder first and tells you not to open it.

Post 2: what it found, which is the screenshot people reply to:

> This is the sample in the repo. Three findings, two of them `hold`:
>
> `tasks.json:9` runs `node .vscode/assets/font-awesome.woff2` on open.
> That `.woff2` is not a font. It is JavaScript. In the real campaign that file steals
> SSH keys, browser data and wallets; the sample in the repo only prints a line.
>
> Nothing was executed to find this. It reads bytes.

Post 3: the one-liner:

```
curl -fsSL https://raw.githubusercontent.com/zahmed333/oss-pulse/main/install.sh -o install.sh
sh install.sh
oss-pulse scan ~/Downloads/the-take-home
```

> It also checks your Python dependencies: whether a release lost its PyPI attestation,
> whether the newest version has code that only exists on PyPI, whether a package name is
> a typosquat.

Post 4: the honest limits, which is what keeps the replies from sinking it:

> What it is not:
> not an antivirus, and not a guarantee. Static heuristics lose to a determined attacker.
> Python-first for dependencies: `scan` reads any folder, `check` reads Python only.
> The "0 false alarms on the top 250 PyPI packages" number was tuned on those same 250.
> Method and limits: docs/benchmarks.md
>
> It is early. Bug reports about false positives are the most useful thing you can send.

Post 5: the ask, and the link:

> If you are job-hunting right now: scan the folder before you open it, and if it says
> hold, report the posting.
>
> github.com/zahmed333/oss-pulse
>
> MIT. `scan` runs offline and uploads nothing.

## Before posting

- [ ] Publish to PyPI so the post can say `uvx oss-pulse` (only the maintainer can).
- [ ] Cut a GitHub release; pin `install.sh` and the Action to that tag, not `main`.
- [ ] Set the repository About text and topics; upload `docs/brand/social-preview.png`.
- [ ] Record the 15 s clip from `docs/brand/demo.svg` (screen recording, not a GIF export:
      X plays MP4 inline and GIFs get compressed to mush).
- [ ] Post the thread, then reply to your own post with the limits from Post 4 within the
      first ten minutes. Corrections posted early read as confidence; corrections posted
      late read as being caught.

## Timing

This attack resurfaces whenever a wave of fake recruiter accounts hits. Keep the thread
drafted and post it the day a new write-up appears: the news supplies the reach, the
thread supplies the answer.

## What not to do

- Do not post a live malicious repository or name a package that has no advisory. That is
  how a launch turns into a legal problem and a pile-on.
- Do not claim it catches everything. The first reply will be "heuristics are useless",
  and the answer to that is the limitations section, not a stronger claim.
- Do not lead with the architecture. The dbt/DuckDB pipeline is genuinely interesting and
  belongs in a follow-up post for the data-engineering crowd, a day later, not in the hook.
